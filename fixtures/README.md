# 回归测试用例

真实报告的**脱敏**提取基准。用于:

1. 评测提取准确率(换模型 / 改 prompt 后跑一遍比对)
2. 验证 `packages/medical` 的自洽校验规则
3. 作为新增字段的需求来源 —— 每个用例都记录了它暴露的设计缺口

## 脱敏规则

以下字段一律替换,**不得提交任何真实个人信息**:

| 字段 | 处理 |
|---|---|
| 姓名 | `测试患儿A` / `测试成人B` |
| 登记号 / 就诊卡号 | `MASKED-001` |
| 门诊号 / 报告编号 / 超声号 | 保留格式,数字部分替换为 `xxxx` |
| 申请医师 / 检验者 / 审核者 | `医师甲` / `医师乙` / `检验甲` |
| 出生日期 | 只保留年龄 |
| **手机号 / 座机** | **整体删除** —— 见 ADR-031,系统本身也不提取 |
| 医院名 | 保留(参考区间与设备上下文所需),院区泛化 |

**原始影像不入库。** 用例只保留期望的提取结果 JSON 与说明文档 —— 图片留在本地或私有存储。

## 基线:26 次规则执行,零失败

跨 4 个真实用例,所有自洽校验**全部通过**。

这不是巧合,是结构性的 —— MCV、MCH、MCHC、PCT、HCO₃⁻、TCO₂、估算体积**都是仪器自己算出来的**,报告输出前这些等式已经成立。

**这条基线是 [ADR-039](../docs/adr.md)(校验驱动的多轮闭环)的实证依据:**

> 报告是自洽的。校验失败时,`P(OCR 读错) >> P(报告本身错)` → 失败应触发"回原图重看",而不是直接标红等人工。

因此每个 fixture 的 `checks` 数组同时承担两个角色:

1. 回归基准 —— 提取正确时这些规则必须全过
2. **闭环的负样本源** —— 故意扰动某个数值(如把 MCHC 341 改成 34.1),应触发重读并被修正

## 使用

```bash
tools/eval-extraction --fixture fixtures/001-pediatric-emergency
```

比对维度:

- **字段级准确率**:数值、单位、参考区间、异常标记逐项比对
- **自洽校验命中率**:期望通过的规则是否全部通过
- **假阳性率**:是否对正常报告误报
- **闭环有效性**:注入已知 OCR 错误后,能否在 3 轮内自动修正
- **`on_failure` 分类正确性**:跨仪器/跨标本差异必须标 `flag` 而非触发重读(否则永不收敛)
