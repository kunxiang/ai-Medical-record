## 一、★★★ 参考区间在 7 天内变了

同一家医院、**同一台 BC-7500-2**、同一个 3 岁 0 月的孩子,相隔 7 天,**27 项中 14 项参考区间不同**:

| 项目 | 08-10(**末梢血**) | 08-17(**静脉血**) |
|---|---|---|
| WBC | 4.90–12.70 | **4.40–11.90** |
| NEUT# | 1.30–6.70 | **1.20–7.00** |
| LYMPH# | 2.00–6.50 | **1.80–6.30** |
| MONO# | 0.16–0.92 | **0.12–0.93** |
| EO# | 0.04–0.74 | **0.00–0.68** |
| BASO# | 0.00–0.10 | **0.00–0.07** |
| NEUT% | 23.0–64.0 | **22.0–65.0** |
| LYMPH% | 26.0–67.0 | **23.0–69.0** |
| EO% | 0.5–9.0 | **0.0–9.0** |
| RBC | 4.10–5.50 | **4.00–5.50** |
| Hb | 115.0–150.0 | **112.0–149.0** |
| HCT | 35.0–45.0 | **34.0–43.0** |
| MCHC | 309.0–359.0 | **310.0–355.0** |
| PLT | 187–475 | **188–472** |

未变的 13 项:MONO%、BASO%、MCV、MCH、RDW-CV、RDW-SD、MPV、PCT、PDW、P-LCR、NRBC#、NRBC%、CRP。

### 原因无法从单据判定

两个候选,**单据本身分辨不了**:

1. **标本类型不同**(末梢血 vs 静脉血)—— LIS 按标本类型切换参考区间
2. **实验室更新了参考区间库**

年龄未跨段(两次都是 3 岁 0 月),排除年龄分段。

### 但工程要求与原因无关

无论哪个原因,结论都一样:

> **参考区间必须跟着每一条数据走。任何形式的缓存、复用、"上次是多少这次应该也一样"都是错的。**

这是 [ADR-006](../../docs/adr.md) 最强的验证。原来的论据是「不同医院参考区间不同」;现在证明:**同一医院、同一仪器、7 天内就会变。**

## 二、★★★ 标本类型必须作为趋势分组维度

同一指标,7 天,两种标本:

| 指标 | 08-10 末梢血 | 08-17 静脉血 | 变化 |
|---|---|---|---|
| WBC | 4.68 | 7.02 | +50% |
| **PLT** | **216** | **417** | **+93%** |
| CRP | 5.9 | 16.7 | +183% |
| Hb | 133 | 130 | −2% |
| HCT | 39.2 | 38.1 | −3% |

**末梢血的血小板计数本身就系统性偏低**(采集过程中血小板聚集黏附于穿刺部位)。

所以 216 → 417 这个差异里,有多少来自标本类型、多少是真实变化,**数据本身分辨不了**。

### 期望行为

```
✅ 趋势按 specimen 分组或显式标注:「末梢血」「静脉血」
✅ 跨标本类型的两点之间不连线,或以虚线 + 警示标注
❌ 直接连线并计算 RCV —— 会得出"变化极显著"的结论,
   而其中混着标本类型的系统性偏差
❌ 任何对变化原因的解读
```

→ `observation.specimen` 与 `device` 同级,是趋势的**分组维度**,不是元数据。

## 三、★★ 一条与用例 001 **相反**的合并规则

COVID 抗原单:

```
NO 1  新型冠状病毒(COVID-19)抗原检测   阴性       阴性       金标法
NO 2  COVID-19 Antigen Test            Negative   Negative   Gold-based LFIA
```

**这两行是同一检测的中英文对照,不是两个项目。** 天真提取 → 两条 observation → 重复计数。

但用例 001 的规则是**同名行不可合并**(氧分压 65 / 氧分压(校正)67)。

| 情况 | 判断依据 | 处理 |
|---|---|---|
| 氧分压 65 / 氧分压(校正)67 | 值与参考区间**不等价** | 保留两条,`qualifier` 区分 |
| 阴性 / Negative | 值与参考区间**语义等价**,方法学对应 | **合并一条**,中文为 `local_name`,英文存 alias |

> ⚠️ 这个区分需要**语义等价性判断**,不是字符串规则。
>
> 两条"规则"方向相反,而我在设计文档里是靠**一段散文**来区分的:「看值和参考区间是否语义等价」。
> 那段散文本质上就是一个 prompt —— 它描述的是判断,不是可编译的条件分支。
> 这是"固定规则表在异质单据面前不收敛"的直接证据,应纳入后续架构审核。

## 四、★★ 页脚图例与实际用法不一致

流感单:**甲型流感病毒抗原检测 = 阳性**,提示列标的是 **`↑`**。

而同一张单的页脚图例明确印着:

```
提示说明:↑:升高;  ↓:降低;  ↑↑↑:危急值;  ↓↓↓:危急值;  ※:阳性
```

**单据自己印的规范与自己的用法对不上。** 按图例硬编码映射 → 阳性结果被漏标。

→ 新增 `observation.abnormal_flag_raw` 保留原始符号;标准化 flag 由**上下文判断**得出,不由符号表查得。

## 五、★ 报告自带的结果解释

COVID 单备注栏(中英双语):

> 阴性结果表示:样本中没有检出新型冠状病毒抗原,但不能完全排除感染,可能与低病毒载量等因素相关,**需结合临床表现**,必要时核酸复查。
> 阳性结果表示:样本中检出新型冠状病毒抗原。

这是**报告原文的一部分**,不是我们生成的解读。

→ 新增 `document.report_notes`,原文保留并标注来源为报告原文,**不得与系统生成内容混淆**。

> 附带印证:连医院自己都在说「不能完全排除」「需结合临床表现」。系统更不该下结论。
