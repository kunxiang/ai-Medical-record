# 08 · 医学参考层

> 本文档是 `packages/medical` 的规格说明。该包为**纯函数 + 纯数据**,零 I/O、零框架依赖。
>
> ⚠️ **本文档中的数值用于工程实现参考,不构成医学建议。** 系统不做诊断、不判定"正常/异常"。标注 🔍 的数值需在实现前核对权威来源。

---

## 1. 三条不可违反的规则

### 1.1 参考区间跟着数据走,不在系统里定义全局标准

不同医院用不同仪器、试剂、方法学,**参考区间本身就不同**。同样的 ALT 45 U/L,在上限 40 的实验室是 ↑,在上限 50 的实验室是正常。

```
✅ observation.ref_low / ref_high  ← 该次报告自带的区间
❌ 系统内置一张"正常值表"用于判定
```

**这一条如果做错,整个系统的可信度归零。**

`packages/medical` 里的参考区间数据**仅用于**:量级合理性校验(如"血糖 580 mmol/L 显然是 OCR 错误")与展示时的上下文说明,**绝不用于判定异常**。

### 1.2 数值必须带单位,永远不存裸数字

单位换算是本项目最容易出错、也最有价值的功能。**类型系统必须强制单位存在。**

### 1.3 派生指标必须记录公式版本

eGFR 用 CKD-EPI 2021 还是旧的 MDRD,结果不同。不记版本,前后不可比。

## 2. 单位换算

### 2.1 换算表

| 指标 | 单位 A | 单位 B | A → B |
|---|---|---|---|
| 葡萄糖 | mmol/L | mg/dL | × 18.016 |
| 总胆固醇 / LDL-C / HDL-C | mmol/L | mg/dL | × 38.67 |
| **甘油三酯** | mmol/L | mg/dL | **× 88.57** |
| 肌酐 | μmol/L | mg/dL | ÷ 88.4 |
| 尿酸 | μmol/L | mg/dL | ÷ 59.48 |
| 尿素 ↔ 尿素氮(BUN) | mmol/L (尿素) | mg/dL (BUN) | × 2.80 |
| 总胆红素 | μmol/L | mg/dL | ÷ 17.1 |
| 钙 | mmol/L | mg/dL | × 4.008 |
| 磷 | mmol/L | mg/dL | × 3.097 |
| 血红蛋白 | g/L | g/dL | ÷ 10 |
| 铁蛋白 | pmol/L | ng/mL | ÷ 2.247 |

> ⚠️ **甘油三酯的系数(88.57)与胆固醇(38.67)不同。** 用同一个系数换算是典型错误 —— 分子量不同。

### 2.2 HbA1c 的两套体系

**这是非线性关系,不能用简单系数。**

```
NGSP (%) = 0.09148 × IFCC (mmol/mol) + 2.152
IFCC (mmol/mol) = (NGSP (%) − 2.152) / 0.09148
```

中国报告普遍用 NGSP %,欧洲部分实验室用 IFCC mmol/mol。

### 2.3 尿素 vs 尿素氮 的陷阱

中国报告"尿素(Urea)mmol/L",美国报告"尿素氮(BUN)mg/dL"。**这不只是单位不同,是两个不同的量**(尿素分子 vs 其中的氮)。混淆会得出错误结论。字典中必须作为两个独立 concept 处理,并提供换算。

### 2.4 实现要求

```ts
// packages/medical/src/units/
export function convertToSi(
  concept: ConceptCode,
  value: number,
  unit: string,
): { value: number; unit: string; version: string } | null;
```

- 单位字符串先归一(`mmol/l`、`mmol/L`、`mmol·L⁻¹` → 同一个)
- 无法识别的单位**返回 null,不猜测**,原值照常入库
- 换算结果记录 `conversion_version`,规则变更时可重跑

## 3. 分析前变异

对结果的影响**经常大于疾病本身**。这些通过 [05 · 情境问答](./05-capture-and-context.md#4-问答模板)采集,存入 `context_answer`,并在趋势图上作为**中性标注**展示。

| 因素 | 主要影响 |
|---|---|
| **空腹状态** | 甘油三酯显著升高;血糖直接失去诊断意义 |
| **采血时间** | 皮质醇、铁、睾酮有明显昼夜节律 |
| **急性疾病 / 感染 / 发热** | 急性期反应:铁蛋白↑、白蛋白↓、**血脂假性降低**(心梗后数周内血脂不可信) |
| **剧烈运动** | CK、AST、肌酐显著升高 |
| **药物** | 他汀→血脂/肝酶;二甲双胍长期使用→B12 降低;利尿剂→尿酸↑、血糖↑、钾钠改变;糖皮质激素→血糖↑、白细胞↑ |
| **月经周期** | 血红蛋白、铁蛋白、部分激素 |
| **体位 / 止血带时间** | 白蛋白、总蛋白、部分脂类(血液浓缩) |
| **溶血 / 脂血 / 黄疸标本** | 钾假性升高;多项指标干扰 |

**展示形式(中性,不解释):**

> 「该次采血为非空腹」
> 「该次报告标注:近两周有发热」

不写"因此血脂偏低不可信"—— 那是医生的判断。

## 4. 参考变化值(RCV)

### 4.1 为什么需要

同一个人今天和明天抽血,数值本来就会波动。**判断两次结果的差异是否真实,不能靠肉眼看折线。**

不做这件事的后果:系统会持续把噪声呈现成趋势,制造无谓的焦虑,并且在医生眼里显得外行。

### 4.2 公式

```
RCV(%) = √2 × Z × √(CVa² + CVi²)

CVa = 分析变异(实验室,通常 2–5%)
CVi = 个体内生物学变异
Z   = 1.96(双侧 95%)
```

### 4.3 CVi 参考值 🔍

**以下为量级参考,实现前应从 [EFLM Biological Variation Database](https://biologicalvariation.eu/) 取当前值。**

| 指标 | CVi ≈ | RCV(95%, CVa=3%)≈ | 含义 |
|---|---|---|---|
| **HbA1c** | 2% | **10%** | 变异极低 → **趋势极其可靠**,0.4% 的变化就可能是真的 |
| 白蛋白 | 3% | 12% | |
| 血红蛋白 | 3% | 12% | |
| 肌酐 | 5% | 16% | |
| 空腹血糖 | 6% | 18% | |
| 总胆固醇 | 6% | 18% | |
| HDL-C | 7% | 21% | |
| LDL-C | 8% | 24% | 从 3.2 涨到 3.5(+9%)大概率是噪声 |
| 尿酸 | 9% | 26% | |
| AST | 12% | 34% | |
| **ALT** | 19% | **53%** | 变异很高 → 从 30 涨到 40(+33%)**大概率只是噪声** |
| **甘油三酯** | 20% | **56%** | 极高,且强烈受空腹状态影响 |
| TSH | 19% | 53% | |

**HbA1c 与 ALT 的对比是这套机制价值的最好说明** —— 同样是"涨了 30%",一个几乎确定是真的,一个几乎确定是噪声。

### 4.4 展示

```
✅ 「本次变化超出该指标的常规生物学波动范围」
✅ 「本次变化在常规波动范围内」
❌ 「你的肝功能在恶化」
```

在趋势图上可画一条 RCV 带,视觉上区分噪声与信号。

### 4.5 实现

```ts
// packages/medical/src/variation/
export function referenceChangeValue(
  concept: ConceptCode,
  opts?: { cva?: number; z?: number },
): { rcvPercent: number; cvi: number; cva: number; source: string } | null;

export function exceedsRcv(
  concept: ConceptCode,
  previous: number,
  current: number,
): boolean | null;   // 数据不足时返回 null,不猜
```

## 5. 推荐监控组

用户可自定义,系统提供预置模板。

### 5.1 「三高+」模板 🔍

针对"三高边缘"人群。**只盯三高是不够的** —— 最容易被漏掉的是早期靶器官损害。

| 组 | 指标 | 说明 |
|---|---|---|
| **血糖** | 空腹血糖、HbA1c、(OGTT 2h) | HbA1c 是趋势之王(CVi 最低) |
| **血脂** | LDL-C、**non-HDL-C**、TG、HDL-C、(ApoB) | non-HDL-C = TC − HDL-C,**非空腹时比 LDL-C 更稳** |
| **血压** | 家庭自测收缩压/舒张压 | **独立数据流**,见 §6 |
| **肾(最易漏)** | 血肌酐 → **eGFR**、**尿白蛋白肌酐比 UACR** | UACR 是三高人群最早期的靶器官损害信号,常被忽略 |
| **肝/代谢** | ALT、AST、GGT、腹部超声脂肪肝结论 | 代谢相关脂肪肝与三高高度共病 |
| **尿酸** | 血尿酸 | 常被称为"第四高",与三高高度相关 |
| **体格** | 体重、**腰围**、BMI | 腰围对代谢风险的预测优于 BMI |
| **血常规** | 血红蛋白、血小板 | 贫血会影响 HbA1c 的解读 |

### 5.2 其他人群模板

| 人群 | 追加维度 |
|---|---|
| **儿童** | 疫苗接种记录、**生长曲线(身高/体重百分位)** —— 儿科最有价值的纵向数据 |
| **育龄女性** | 月经史、孕产史、铁蛋白、甲功 |
| **老人** | 用药清单(最重要)、肾功能、电解质、B12/叶酸 |

## 6. 血压:必须独立处理

**诊室血压不适合做趋势。** 有白大衣效应,单次值噪声很大,而且**不同测量方式的阈值不同**:

| 测量方式 | 高血压诊断阈值 🔍 |
|---|---|
| 诊室血压 | ≥ 140/90 mmHg |
| **家庭自测** | ≥ 135/85 mmHg |
| 动态血压 24h 平均 | ≥ 130/80 mmHg |
| 动态血压 白天 / 夜间 | ≥ 135/85 / ≥ 120/70 mmHg |

### 数据模型要求

`observation` 上必须有区分字段:

```
concept_code = BP_SYSTOLIC / BP_DIASTOLIC
measurement_setting = office | home | ambulatory_24h | ambulatory_day | ambulatory_night
```

**不同 setting 的数据不能画在同一条趋势线上。**

### 家庭自测的标准化流程(录入时提示)

- 静坐休息 5 分钟
- 连续测 2–3 次,间隔 1 分钟,取平均
- 早晚各一次(晨起服药前、睡前)
- 记录左右臂

血压走**手动录入**数据流,不从化验单 OCR。

## 7. 派生指标

系统自动计算并存为 `observation`(`is_derived = true`),**必须记录 `derived_formula`**。

### 7.1 eGFR — CKD-EPI 2021(去种族系数)

```
Scr 单位:mg/dL(μmol/L 需先 ÷ 88.4)

κ = 0.7(女) / 0.9(男)
α = −0.241(女) / −0.302(男)

eGFR = 142
     × min(Scr/κ, 1)^α
     × max(Scr/κ, 1)^(−1.200)
     × 0.9938^年龄
     × 1.012(女性)
```

单位:mL/min/1.73m²

> **必须记录用的是 CKD-EPI 2021 还是旧的 MDRD** —— 两者结果不同,不记版本则前后不可比。
> 需要:准确的 `birth_date` 与 `sex_at_birth`。这就是为什么这两个字段是 `person` 的必填项。
> 儿童应使用 Schwartz 公式,不适用本式 —— 未成年时应拒绝计算而非给出错误值。

### 7.2 non-HDL-C

```
non-HDL-C = 总胆固醇 − HDL-C
```

**非空腹样本中比 LDL-C 更稳定**,值得自动派生并纳入监控组。

### 7.3 LDL-C 的方法学陷阱 🔍

- **直接测定法** vs **Friedewald 计算法**结果不同
- Friedewald 公式在 **TG > 4.5 mmol/L 时失效**

→ `observation.method` 必须保留;两种方法的数据在趋势图上应当**可区分标注**。

### 7.4 BMI / 腰围身高比

```
BMI = 体重(kg) / 身高(m)²
WHtR = 腰围 / 身高
```

需要同一时间点的身高体重 observation。

### 7.5 心血管风险评估 🔍

若未来实现,**中国人群应使用 China-PAR 模型**,而非美国的 PCE 或 Framingham —— 后两者会高估中国人群风险。

> 这属于"风险评估",已接近 [非目标](./00-vision-and-scope.md#3-非目标)边界。若实现,必须明确标注模型来源与适用人群,且不给出任何行动建议。

## 8. 诊断阈值:记录差异,不做判定

**系统不硬编码诊断标准去判定"正常/异常"。** 因为标准本身不统一:

| 指标 | 标准 A | 标准 B |
|---|---|---|
| **空腹血糖受损(IFG)** | WHO / 中国:**6.1–6.9** mmol/L | ADA:**5.6–6.9** mmol/L |
| 糖尿病诊断 🔍 | FPG ≥ 7.0 / 2hPG ≥ 11.1 / HbA1c ≥ 6.5% | 基本一致 |
| LDL-C 目标值 🔍 | 按 ASCVD 风险分层,不同风险等级目标不同 | 各国指南略有差异 |

**同一个 6.5 mmol/L 的空腹血糖,按中国标准是"糖尿病前期",按 ADA 标准也是 —— 但 5.8 就只有 ADA 认为异常。**

### 允许的展示方式

```
✅ 数值 3.62 mmol/L,该报告参考区间 0–3.37(北京协和医院)
✅ 参考:该指标常见诊断阈值 —— WHO/中国 6.1,ADA 5.6(标注来源)
❌ 「你的血糖异常」
❌ 「你处于糖尿病前期」
```

阈值可以作为**明确标注来源的参考线**出现在图表上,但系统永远不渲染结论。

## 9. HbA1c 的解读限制

HbA1c 是最好的趋势指标(CVi 最低),但在以下情况会**系统性失真** 🔍:

| 情况 | 影响 |
|---|---|
| 贫血(缺铁性 / 溶血性) | 可能假性升高或降低 |
| 血红蛋白变异体(如地中海贫血) | 部分检测方法结果不可靠 |
| 慢性肾病、近期输血 | 失真 |
| 妊娠 | 参考意义改变 |

**实现方式:** 当同期存在异常血红蛋白或已知血红蛋白病时,在 HbA1c 数据点旁显示中性提示 ——「同期血红蛋白 92 g/L」——**陈述事实,不下结论**。

## 9b. 影像报告的纵向追踪

### ⚠️ 结论「消失」不等于问题消失

真实案例(同一儿童,相隔两年):

| | 2024-08-25(1 岁 · **外科门诊**) | 2026-08-17(3 岁 · **内科急诊**) |
|---|---|---|
| 检查目的 | **专查**阴囊 + 腹股沟,含「哭闹时」诱发动作 | **主查**胃肠道 + 阑尾,阴囊顺带 |
| 结论 1 | 右侧精索、睾丸鞘膜积液 | 右侧睾丸鞘膜积液 |
| 结论 2 | **左侧鞘状突未闭** | — |

第二条结论在新报告里没有出现。**但这不是"好转"** —— 两次检查的覆盖范围与手法根本不同:第一次是外科专项检查并做了诱发动作,第二次是急诊顺带扫查。

**系统必须做到:**

```
✅ 并列呈现两次结论,并显式标注检查覆盖范围不同
✅ 「本次检查项目不包含 X,该项无本次数据」
❌ 把「未提及」渲染成「已消失」「已好转」
❌ 对两次结论做任何差异解读
```

→ 实现依赖 `document.exam_items`。**不记录覆盖范围,就无法区分"查了没发现"与"根本没查"** —— 这两者在临床上天差地别。

### 影像测量值的纵向可比性

| 要求 | 做法 |
|---|---|
| 左右侧分开 | `body_site` 作为序列维度,不合并 |
| 旧报告缺派生值 | 用同一公式补算(如椭球体积),置 `is_derived` + `derived_formula` |
| 不同设备/术者 | 记录 `device`;超声测量的操作者依赖性高于化验 |
| **无参考区间** | 报告本身不给 —— 系统**绝不做正常/异常暗示** |

### 「顺带检查」是本项目的核心场景

2026 那次超声是为查腹泻开的腹部超声,**顺带扫了阴囊**,于是产生了鞘膜积液的随访数据。

这正是项目最初要解决的问题:「每次检查不一定针对该问题,但顺带查到的值应能纳入长期记录」。

→ 监控组必须支持三类条目(化验指标 / 影像测量 / 影像结论标签),见 [03 · 数据模型](./03-data-model.md#metric_group--metric_group_item)。

## 9c. 给药事件与检验值的时间对齐

真实案例(同一次急诊):

| 时刻 | 事件 |
|---|---|
| 17:07 | 采血 —— 血气 HCO₃⁻ 19.5 ↓、碱剩余 −5 |
| 18:02 | 开始输液 —— 葡萄糖 + 氯化钠 + **氯化钾** + 维生素B6 + 西咪替丁 |

**补钾补钠补糖之后再抽血,电解质与血气结果与输液前不可同日而语。**

这是 [§3 分析前变异](#3-分析前变异)里「药物影响」的最强形态 —— 不是「最近在吃什么药」,而是「**两小时前静脉输了什么**」。

**实现要求:**

- `medication.administered_at` 精确到分
- 趋势图上给药事件与检验时间点**对齐显示**(时间轴叠加,不是分开两张图)
- 中性标注:「该次采样时间早于本次输液」/「该次采样在输液开始后 3 小时」
- **不解读影响方向** —— 不写"因此钾偏低不可信"

## 11. 特殊人群的参考区间

### 儿童 🔍

**拿成人标准看孩子的化验单会得出完全错误的结论。**

| 指标 | 儿童特点 |
|---|---|
| **碱性磷酸酶 ALP** | 生长期显著高于成人(骨源性)—— 按成人上限看会被误判为异常 |
| **白细胞分类** | 婴幼儿以**淋巴细胞为主**,而非中性粒细胞 |
| 血红蛋白 | 随年龄段变化 |
| 肌酐 / eGFR | 需用 Schwartz 公式,CKD-EPI 不适用 |

→ `concept.age_dependent_reference = true` 的指标,在儿童身上应**抑制任何量级警告**,只呈现报告自带的区间。

#### 真实印证(用例 001,3 岁男童)

儿童医院血球仪给出的参考区间:

| 指标 | 儿科区间(该报告) | 成人区间(常见) |
|---|---|---|
| 中性粒细胞比例 | **22.0 – 65.0 %** | 约 40 – 75 % |
| 淋巴细胞比例 | **23.0 – 69.0 %** | 约 20 – 40 % |
| 血红蛋白 | 112 – 149 g/L | 男 130 – 175 g/L |

这正是"婴幼儿以淋巴细胞为主"的量化体现 —— **一个 3 岁孩子淋巴细胞占 60% 是正常的,按成人区间看却像淋巴细胞增多。**

### ⚠️ 12. 设备自带的成人区间

同一份用例暴露了一个更细致的问题:**不是系统用错了标准,是报告本身自带的区间就不是儿科的。**

急诊血气仪(iSTAT1-300G)给 3 岁患儿的报告上,血红蛋白参考区间印的是 **12–17 g/dL**(≈ 120–170 g/L)—— 这是**成人男性范围**;而同一天同一管血,儿童血球仪用的是 112–149 g/L。血气仪出厂默认成人区间,不按患者年龄切换。

**系统的处理方式:**

```
✅ 忠实照抄报告自带的区间(ADR-006 不动摇)
✅ 检测到冲突时给中性提示:
   「该报告的参考区间(12–17 g/dL)与同期另一份报告
     的同一指标(112–149 g/L)不一致」
❌ 自己"纠正"成儿科区间
❌ 判定哪个区间才对
```

陈述事实,把判断留给医生。

### ⚠️ 12b. 参考区间的漂移是常态,不是例外

[用例 004](../fixtures/004-influenza-visit/) 提供了本项目最强的一条实证:

> **同一家医院、同一台 BC-7500-2、同一个 3 岁 0 月的孩子、相隔 7 天 —— 27 项中 14 项参考区间不同。**

| 项目 | 08-10(末梢血) | 08-17(静脉血) |
|---|---|---|
| WBC | 4.90–12.70 | 4.40–11.90 |
| NEUT# | 1.30–6.70 | 1.20–7.00 |
| LYMPH% | 26.0–67.0 | 23.0–69.0 |
| Hb | 115.0–150.0 | 112.0–149.0 |
| HCT | 35.0–45.0 | 34.0–43.0 |
| PLT | 187–475 | 188–472 |

年龄未跨段(两次都是 3 岁 0 月)。可能原因:LIS 按标本类型切换区间,或实验室更新了区间库 —— **从单据无法判定**。

**但工程要求与原因无关:参考区间必须跟着每一条数据走。** 原本 §1.1 的论据是「不同医院不同」;现在证明**同一医院、同一仪器、7 天内就会变**。

### 12c. 标本类型是趋势的分组维度

| 指标 | 08-10 **末梢血** | 08-17 **静脉血** | 变化 |
|---|---|---|---|
| PLT | 216 | 417 | **+93%** |
| WBC | 4.68 | 7.02 | +50% |
| CRP | 5.9 | 16.7 | +183% |
| Hb | 133 | 130 | −2% |

**末梢血(指尖/足跟)与静脉血的血细胞计数存在系统性差异**,血小板尤其明显 —— 采集过程中血小板在穿刺部位聚集黏附,计数偏低。

因此 216 → 417 里,标本类型贡献多少、真实变化多少,**数据本身分辨不了**。

```
✅ 趋势按 specimen 分组,或虚线连接 + 标注「标本类型不同」
❌ 实线连接并计算 RCV —— 会得出"变化极显著",而其中混着系统性偏差
❌ 任何对变化原因的解读
```

→ `specimen` 与 `device` 同级,是**分组维度**,不是元数据。

### 13. 同一管血,不同仪器

用例 001 中,17:07 一次采血同时上了两台仪器:

| | 血气 iSTAT1-300G | 血常规 BC-7500-2 | 差异 |
|---|---|---|---|
| 血红蛋白 | 12.60 g/dL = **126 g/L** | **130 g/L** | 3.1% |
| 红细胞比容 | **37 %** | **38.1 %** | 2.9% |

**两个数都是对的。** 方法学不同:

- iSTAT 测导电率得 HCT,再按 `Hb(g/dL) = HCT(%) × 0.34` **推算** Hb(实测:37 × 0.34 = 12.58 ≈ 12.60 ✓)
- BC-7500 用比色法**实测** Hb

**对趋势的影响:**

| 要求 | 实现 |
|---|---|
| 不能画成"同一天两个 Hb" | 趋势按 `device` 分组或标注来源 |
| 优先用实测值 | 同一指标同时存在 `measured` 与 `calculated` 时,趋势默认取 `measured` |
| 跨仪器偏差监控 | `cross_device_agreement` 规则:归一后偏差 > 10% 才标记(3% 属正常) |

> 这条规则的真正价值不是发现仪器差异 —— 而是**抓单位换算错误**。若一边 126 一边 1300,立刻暴露。

### 性别 🔍

参考区间按性别分的常见指标:血红蛋白、血肌酐、尿酸、铁蛋白、部分激素。

→ 这就是 `person.sex_at_birth` 为必填字段的原因。
