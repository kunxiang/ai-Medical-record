# 09 · 路线图

## 0. 排序原则

**归档能力抢时间,医学能力慢慢长。**

- 热敏纸在褪色,旧单据在丢失,情境记忆在过期 —— 这些**有时效性**,先做
- 医学解读能力可以在存量数据上后补 —— 因为原件在手,派生层随时可重生

因此:先把管道打通,再谈智能。

---

## M0 · 地基

**目标:能把一张照片安全地存进去,并且五年后还能读。**

- [ ] Monorepo 骨架(`apps/api`、`apps/web`、`packages/contracts`、`packages/storage`)
- [ ] `packages/contracts` 首版:person / document / encounter 类型与 Zod schema
- [ ] PostgreSQL schema + Drizzle 迁移(见 [03 · 数据模型](./03-data-model.md))
- [ ] S3 桶创建:**versioning + object lock 必须在建桶时开启**(事后无法补)
- [ ] `packages/storage`:key 生成/解析 + sidecar 序列化 + 往返测试
- [ ] 账号认证 + `person_access` 授权中间件(**从第一天起所有查询都过这一层**)
- [ ] 建档 API

**验收:** 用 curl 建一个 person,上传一张图,能在 S3 里用 `rclone ls` 看到人类可读的路径与 sidecar。

---

## M1 · 归档管道(P0 核心)

**目标:拍照 → 入库,弱网可用。这一步做完,系统就已经有价值了。**

- [ ] 预签名 URL 直传
- [ ] `POST /documents` + 幂等键(`client_document_id`)
- [ ] PWA:拍照(含连拍模式)、PDF/截图/相册导入
- [ ] **IndexedDB 离线队列 + Service Worker 后台重试**
- [ ] 上传队列状态 UI(「3 张待上传」)
- [ ] sidecar JSON 写入 S3
- [ ] 缩略图 / 预览图生成
- [ ] 文档浏览:按人 → 时间轴 → 文档

**验收:** 飞行模式下拍 5 张 → 恢复网络 → 全部上传成功,一张不丢。

> ⏰ **此时开始抢救存量:** 系统一可用就集中扫描家里的旧单据,越老的越优先。热敏纸在褪色。

---

## M2 · AI 元数据与归人

**目标:不用手填任何东西,系统自己知道这是谁、什么时候、哪家医院、什么单子。**

- [ ] Claude 视觉调用封装 + prompt 版本管理
- [ ] Stage 1:分类 + 元数据 + **全文提取**
- [ ] **本地归人确认 + 上传后 AI 对账告警(person_mismatch)**(ADR-041)(见 [07 · API](./07-api-contract.md#归人建议可选前置调用))
- [ ] facility 归一(AI 判断 + normalization_decision 缓存,ADR-040)
- [ ] encounter 自动归组建议(同人 + 同机构 + 时间窗,AI 判断,ADR-037/040)
- [ ] 后台任务队列 + 状态查询
- [ ] `stop_reason: refusal` 与失败降级处理

**验收:** 上传一叠混合单据,类型/日期/医院识别准确率可测;归人从不静默默认。

---

## M3 · 情境问答

**目标:把过期就拿不回来的信息留住。**

- [ ] 问答模板引擎 + 版本化模板文件
- [ ] 化验单 / 影像 / 处方 / 体检 / 通用 五套模板
- [ ] 按住说话录音(iOS Safari 权限流程)
- [ ] 分段音频上传 + S3 归档
- [ ] ASR 接入(**选型前用真实录音实测中文医学术语**)
- [ ] 转写后的 Claude 结构化抽取
- [ ] 当天补录推送提醒
- [ ] 条件问题(女性月经周期等)

**验收:** 在医院场景下,拍照 + 现场问答总耗时 < 90 秒,且可全程跳过。

---

## M4 · 检索

**目标:五年后能找到。**

- [ ] 维度筛选(人/时间/医院/科室/类型)
- [ ] 全文关键词(`pg_trgm` 起步)
- [ ] embedding 生成 + `pgvector` 语义检索
- [ ] 混合排序 + 结果高亮
- [ ] 就诊事件视图(一次就诊的全部材料)
- [ ] 移动端检索 UI

**验收:** 用模糊记忆("那次转氨酶高的检查")能在一分钟内找到目标单据。

---

## M5 · 结构化提取

**目标:把数值变成可计算的数据。**

- [ ] `normalization_decision` 决策缓存 + 确认队列(概念映射 / 单位识别 / 行合并,ADR-040)
- [ ] `packages/medical`:换算与派生算术 + **算术自洽校验**(执行层,确定性)
- [ ] 校验驱动的闭环重读(ADR-039):失败定位 → 裁剪重读,最多 3 轮
- [ ] Stage 2:按 doc_type 分支的结构化提取
- [ ] `source_bbox` 提取与原图定位 UI(点数值 → 高亮原图位置)
- [ ] observation 落库 + 归一化
- [ ] **待核查队列**(低置信 / 校验失败 / 双次提取分歧)
- [ ] 人工修正流程 + audit_log
- [ ] 双次提取取差集(高价值文档)
- [ ] 重跑工具 `tools/reextract`(**保护已确认记录**)
- [ ] 回归样本集 + 准确率评测脚本

**验收:** 抽查 50 张化验单,提取准确率可量化;所有 OCR 错误都能被校验或人工核查捕获。

---

## M6 · 指标监控与趋势

**目标:把散落的数值变成医生看得懂的趋势。**

- [ ] 参考区间处理(按性别/年龄,来自报告本身)
- [ ] RCV 计算 + 趋势图上的波动带
- [ ] 派生指标:eGFR(CKD-EPI 2021)、non-HDL-C、BMI
- [ ] 监控组管理 + 「三高+」预置模板
- [ ] **血压独立数据流**(手动录入 + measurement_setting 区分)
- [ ] 趋势图(跨医院单位归一,标注数据来源)
- [ ] 情境标注叠加(非空腹 / 近期发热 / 用药变更)

**验收:** LDL-C 三年趋势图能正确显示跨三家医院的数据,单位统一,参考区间各自标注。

---

## M7 · 就诊导出

**目标:能在诊室里被医生真正采用。**

- [ ] 一页纸 PDF:趋势表 + 关键事件时间轴
- [ ] 原件附录(可选)
- [ ] 每个数值的溯源标记
- [ ] **明确不含任何 AI 解读与结论**
- [ ] 分享链接(有效期可控)

**验收:** 打印出来给医生看,3 秒内能看懂,且愿意采信。

---

## M8 · 加固

**目标:让档案活得比应用久。**

- [ ] 第二处备份(rclone 定时同步)
- [ ] 每月完整性校验(sha256 比对 + 数据库↔S3 双向对账)
- [ ] `tools/rebuild-index`:从 S3 manifests 完全重建数据库
- [ ] **恢复演练**(半年一次)
- [ ] 批量导入工具(存量单据)
- [ ] 数据导出(全量 zip + JSON)

**验收:** 删掉整个数据库,能从 S3 完全重建,**含人工层(修正/问答/归组/决策)零丢失**(design-debt D1)。

## 依赖关系

```
M0 地基
 └─> M1 归档管道 ★ 有价值的最小系统
      ├─> M2 AI 元数据 ──> M4 检索
      ├─> M3 情境问答  ★ 抢时间
      └─> M5 结构化提取 ──> M6 趋势 ──> M7 导出
M8 加固 —— 可与 M4 之后任意阶段并行,越早越好
```

**M1 完成即可日常使用。** 之后每一步都是在已积累的存量数据上增值 —— 这正是"归档优先"排序的意义:早一天开始存,数据资产就多一天。
