# 00 · 愿景与范围

## 1. 问题

**病历是碎片化的。** 一次就诊产生一叠纸,散落在抽屉、包里、手机相册。跨医院、跨科室、跨年份的记录之间毫无关联。

具体后果:

- **找不到。** 两年前的化验单已经不知去向。
- **看不清。** 很多医院用热敏纸打印,一两年后字迹变淡甚至空白 —— 即使找到也没用了。
- **不可比。** 不同医院的参考区间、单位、方法学都不一样,单据摆在一起也难以直接对照。
- **没有趋势。** 每一次检验都是孤立截面。医生看到一个边缘值时最想知道"以前是多少",而这个问题通常无解。
- **情境丢失。** 是不是空腹?当时在吃什么药?那阵子有没有生病?这些决定数值如何解读的信息,几周后就想不起来了。

## 2. 目标

按优先级排序。**顺序本身就是设计决策** —— 归档能力是地基,医学能力在其上逐步生长。

### P0 — 归档(DMS)

> 存得下、找得到、活得久。

- 拍照/上传 → 数秒内完成,弱网可用
- 自动识别:人、日期、医院、科室、文档类型
- 按 **人 → 就诊事件 → 文档** 三层组织
- 按关键词 / 时间 / 医院 / 科室 / 类型 / 人 检索,并支持模糊语义检索
- 原件永久保存,任何时候可查看、可导出

### P1 — 情境记录

> 影像里没有的信息,过期就永远拿不回来。

- 拍照后的引导式问答(文字提问 + 按住说话)
- 分现场必答 / 当天补录 / 随时可补三个层次
- 音频与转写文本一同保存,转写可重跑

### P2 — 结构化提取

> 可重跑、可版本化的派生层。

- 从化验单提取指标名、数值、单位、参考区间、异常标记
- 记录提取所用的模型与 prompt 版本
- 算术自洽校验自动标出可疑数值
- 每个数值可点回原图对应位置

### P3 — 指标监控与趋势

- 用户自定义监控组(如"三高")
- 跨医院单位归一后的趋势图
- 基于参考变化值(RCV)标注"本次变化是否超出常规生物学波动"

### P4 — 就诊导出

- 一页纸:指标趋势表 + 关键事件时间轴
- 每个数值可溯源到原始报告影像
- PDF / 图片 / 分享链接

## 3. 非目标

明确**不做**的事,以及原因:

| 不做 | 原因 |
|---|---|
| 诊断、鉴别诊断、疾病概率 | 越界;会降低材料在医生眼中的可信度,并带来不必要的责任 |
| 治疗建议、用药建议、剂量调整 | 同上 |
| "你可能有 XX 病"式的警报 | 制造焦虑,且极易出错 |
| 判定检验结果"正常/异常" | 参考区间是实验室特异的,应原样呈现报告自带的区间 |
| 提醒"你该做 XX 检查了" | 滑向诊疗建议。可以做中性事实陈述:"距上次 HbA1c 已 14 个月" |
| 与医院 HIS/LIS 对接 | 个人使用不具备条件;拍照是唯一现实的输入方式 |
| 医疗器械/软件资质 | 定位为个人档案工具,不作为医疗器械 |
| 多租户 SaaS(初期) | 见架构文档 —— 结构上为多用户预留,但初期只服务单账号 |

## 4. 允许的中性提示

不做结论,但以下**纯数据性**的呈现是允许且有价值的:

- 「本次较上次变化超出该指标的常规生物学波动范围(RCV)」
- 「该次采血为非空腹,甘油三酯结果可能受影响」
- 「本次报告来自 A 医院,参考区间与既往 B 医院不同」
- 「距上次同类检查 14 个月」
- 「OCR 置信度低,建议核对原件」

这些是**关于数据本身的陈述**,不是关于健康状况的判断。

## 5. 用户与场景

### 主要用户

- **档案所有者**(账号持有人):自己拍照、录入、检索、导出
- **家庭成员**(被代理人):不使用应用,由所有者代为建档与上传

初期为**单账号多档案**模型 —— 不是多用户系统。见 [01 · 系统架构](./01-architecture.md#多用户演进)。

### 核心场景

| 场景 | 地点 | 时长要求 |
|---|---|---|
| 拿到化验单立即拍照存档 | 医院走廊、检验科门口(信号差) | < 10 秒 |
| 回答现场必答问题 | 同上 | < 60 秒 |
| 当天晚上补录医嘱与用药 | 家里 | < 3 分钟 |
| 就诊前查找某次旧检查 | 家里或路上 | < 1 分钟 |
| 就诊时把趋势表给医生 | 诊室 | 一页纸,3 秒看懂 |
| 批量导入历史存量单据 | 家里,一次性 | 不限 |

## 6. 成功标准

这个项目在以下条件下算成功:

1. **坚持得下去** —— 一年后仍在用,且没有漏掉的单据
2. **找得到** —— 任意一份三年前的单据,一分钟内能翻到并看清
3. **医生愿意看** —— 导出的一页纸能在诊室里真正被采用
4. **数据没丢** —— 应用换代、账号变更、服务商更替都不影响档案完整性

反过来,以下情况算失败:

- 因为录入麻烦而少存了单据(档案有缺口)
- OCR 错误未被发现,污染了趋势图
- 把父母的数据混进了自己的档案
- 应用停止维护后,档案变成一堆无法解读的二进制
